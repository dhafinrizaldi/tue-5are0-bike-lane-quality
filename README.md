# Assessing Bicycle Lane Quality Using Smartphone Sensor Data

5ARE0 Assignment 1, Group 11: Pedro Gómez Toja, Dhafin Praditya Rizaldi, Alvaro Huisman

Classifies bicycle-lane surfaces as **smooth** or **bumpy** from smartphone accelerometer, gyroscope and gravity data. Four unsupervised and four supervised models are compared, and the selected model (logistic regression) is deployed on an external ride to map its smooth and bumpy sections.

## Setup

1. Create and activate the conda environment:
   ```
   conda env create -f environment.yml
   conda activate bike-lane-quality
   ```
2. Open `group11.ipynb` with the `bike-lane-quality` kernel. Keep `data/` and `DeploymentData/` next to the notebook, because it reads them by relative path.
3. Run all cells. The notebook regenerates `data/processed/` from `data/raw/` and needs no other files.

## Dataset

### Collection protocol
- **Participants:** three group members, each riding with their own phone (iPhone 12, iPhone 15, iPhone 15 Pro Max).
- **App:** Sensor Logger, recording the accelerometer, gyroscope and gravity sensor at 100 Hz with standardisation enabled. All other sensors were off.
- **Phone placement:** fixed to the bicycle handlebar with a phone holder, so the orientation was the same in every trial.
- **Riding:** about 60 seconds per recording at a normal speed of 15–18 km/h.
- **Surfaces:** *smooth* is a well-maintained red cycling lane. *Bumpy* is a lane in regular use with noticeable but safe imperfections, such as cracks and uneven paving.
- **Quantity:** 5 smooth and 5 bumpy recordings per participant, so 30 recordings in total (15 smooth and 15 bumpy).

### File structure
```
data/raw/<label>/<recording timestamp>/
    Accelerometer.csv              time, seconds_elapsed, z, y, x
    Gyroscope.csv                  time, seconds_elapsed, z, y, x
    Gravity.csv                    time, seconds_elapsed, z, y, x
    Metadata.csv                   device name, platform, sample rates, ...
    AccelerometerUncalibrated.csv, GyroscopeUncalibrated.csv,
    Annotation.csv, Tags.csv       recorded by the app, not used
```
- `<label>` is `smooth` or `bumpy`; the folder gives the class label.
- `<recording timestamp>` is the start time of the recording and identifies it.
- `time` is in nanoseconds since the epoch, and `seconds_elapsed` is counted from the start of the recording.
- The phone in `Metadata.csv` identifies the device, which the per-phone normalization uses.

### Processed data
`data/processed/` mirrors `data/raw/` and keeps only the accelerometer, gyroscope, gravity and metadata files. The first and last 10 seconds of each recording are removed, which drops the handling of the phone. The signals are then resampled onto a uniform 100 Hz grid.

### Deployment data
`DeploymentData/` contains one external ride (about 17 minutes after trimming) in the same Sensor Logger format, from an unknown phone without metadata.
